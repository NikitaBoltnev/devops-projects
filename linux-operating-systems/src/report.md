В любом случае видно 2 сетевых интерфейса: `lo` и `enp0s3`.  
`lo` — так называемый петлевой интерфейс (loopback interface). Он присутствует в Linux-системах. Он используется для отладки сетевых программ и запуска серверных приложений на компьютере. Пакеты, отправленные на адрес данного интерфейса, после чего возвращаются обратно, не покидая систему. Это необходимо для локальной связи между процессами на одном компьютере. Т.е. данный интерфейс необходим для того, чтобы компьютер мог взаимодействовать с самим собой, как с отдельным устройством.  

`enp0s3` — это интерфейс для взаимосвязи виртуальной машины и операционной системы на ноутбуке. Я использовал тип подключения `NAT` (по умолчанию), значит машина получает доступ к сети через хостовую операционную систему, в данном случае ноутбук, который подключен к Wi-Fi.


4. Получил IP-адрес устройства, на котором работаю, от DHCP-сервера.  
Для этого использовал команду `ip a`, это сокращение команды `ip address show`.

![Проблема с фото!](screenshots/part3.7.png)
<figcaption>Скриншот с выводом данной команды, меня интересует второй номер, вторая строка "inet ... dynamic enp0s3", слово "dynamic" указывает, что IP выдан DHCP-сервером.</figcaption>

В данном выводе необходим исключительно IP-адрес, опустил петлевой интерфейс, т.к. он имеет стандартный localhost-адрес, ограниченный данным компьютером.  
Обращаю внимание на вывод для `enp0s3`.  
Здесь видно адрес `10.0.2.15` — это `IPv4-адрес`.  
Также видно маску подсети в нотации `CIDR`. `/24` — она позволяет определить, какая часть адреса относится к сети, созданной виртуальной машиной в режиме `NAT` `10.0.2`, а какая к хосту, т.е. уникальный идентификатор виртуальной машины `15`.  
Также видно широковещательный адрес для подсети `brd 10.0.2.255`, он используется для отправки пакетов всем устройствам подсети, это необходимо для настройки, тестирования и диагностики, например, чтобы определить, какие устройства подключены к сети.  
Помимо этого видно надпись `scope global dynamic enp0s3`.

`scope global` указывает, что адрес используется для глобальной сети, т.е. для связи с другими устройствами.  
`dynamic`, как говорилось раньше, указывает, что IP выдан DHCP-сервером.  
`enp0s3` — это имя интерфейса.

Также есть вывод `inet6 fe...` и `inet6 fd...`.  

`inet6 fe` — это адрес типа IPv6 для связи в пределах одного сегмента сети. Например, два устройства, находящиеся в одном сегменте сети, смогут обмениваться пакетами в обход маршрутизатора, напрямую, используя Link-Local адреса.  
`inet6 fd` — это адрес типа IPv6 для связи в пределах частных сетей. Два устройства, находящиеся в одной сети, также смогут обмениваться пакетами напрямую, но используя Unique Local Addresses (ULA).  

Возвращаюсь к `DHCP`.  
`DHCP` (Dynamic Host Configuration Protocol) — это сетевой протокол для автоматического назначения IP-адреса и других параметров устройств внутри сети. При подключении к сети устройство отправляет запрос в сеть, чтобы найти `DHCP-сервер`. На данном сервере происходит обработка данного запроса, и на устройство отправляется ответ, в котором содержится выделенный IP-адрес и иные параметры сети (маска подсети, шлюз по умолчанию (для выхода из локальной сети в другие сети), `DNS-сервер` (для преобразования доменных имен в IP-адреса), доменные имена, время на выделение IP-адреса и т.д.). После этого клиент принимает данное предложение, и сервер подтверждает выделение IP-адреса и других параметров. Это позволяет избежать ручной настройки IP-адреса, что экономит время, также позволяет избежать ошибок, когда два устройства получают одинаковый IP-адрес, а также появляется большая гибкость в настройках сети.

4. Для отображаения процесса с помощью `ps` я использовал ключ `axu`. Он является универсальным ключом, чтобы увидеть все процессы на сервере. 
Команда полностью: `ps axu | grep sshd`.

Разбираю команду подробнее.  
`ps` — команда для отображения процессов, запущенных в системе.  
`a` — указывает, что нужно вывести процессы всех пользователей, кроме процессов, не связанных с терминалом.  
`x` — указывает, что необходимо также вывести процессы, не связанные с терминалом.  
`u` — позволяет увидеть пользователя, чьи разрешения на доступ к файлам используются процессом.  
`|` — данный символ перенаправляет вывод команды `ps` на вход второй части команды, т.е. `grep`.  
`grep` — утилита для поиска строк, содержащих определенные данные.  
`sshd` — вхождение, которое ищет команда `grep`.

![Проблема с фото!](screenshots/part8.5.png)
<figcaption>Вывод команды.</figcaption>

Видно пользователя, который запустил процесс, идентификатор процесса, % использования CPU процессом, % использования памяти процессом, используемую виртуальную память, используемую физическую память, терминал, к которому привязан процесс, состояние процесса, время запуска процесса, время CPU, затраченное на выполнение процесса, команда, которая запустила процесс.

`netstat` — это утилита для получения информации о сетевых соединениях.  
`t` — указывает, что нужно отображать только TCP (Transmission Control Protocol) соединения, оно отвечает за надежную передачу данных между устройствами в сети.  
`a` — указывает, что нужно отображать все соединения и прослушивающие порты, а не только активные.  
`n` — указывает, что нужно отображать адреса и порты в числовом формате.  

`proto` — протокол, который используется для соединения. В случае IPv4 — `tcp`, в случае IPv6 — `tcp6`.  
`Recv-Q` — количество полученных байт, но еще не обработанных приложением.  
`Send-Q` — количество отправленных байт, но еще не подтвержденных.  
`Local Address` — это адрес и порт, который принадлежит устройству, на котором установлено соединение, данное устройство принимает входящие соединения именно на этот адрес.  
`Foreign Address` — это адрес другого устройства, которое подключается к серверу.  
`State` — состояние соединения.  

`0.0.0.0:`  
В контексте `Local Address` означает, что сервер слушает на всех доступных сетевых интерфейсах `0.0.0.0:port`. Т.е. это дает возможность подключиться к любому адресу сервера.  
В контексте `Foreign Address` означает, что сервер готов принимать соединение с любых адресов и портов `0.0.0.0:*`. Т.е. это дает возможность подключиться с любого адреса.
